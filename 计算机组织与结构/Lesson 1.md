# Lesson 01｜基本概念与计算机演化

> [!abstract] 本课主线
> **架构（做什么）→ 组织（怎么做）→ 硬件（用什么实现）**  
> 理解计算机时，既要从上到下拆解其结构，也要从功能需求反推结构设计。贯穿课程的两条设计主线是：**平衡（Balance）** 与 **并行（Parallelism）**。

## 一、计算机和本课程的介绍

1. **介绍**：**《计算机组织与结构》**，简称“计组”，是计算机专业的一门重要的基础课，其包括**计算机组成原理**和**计算机体系架构**两个部分，组成原理主要讨论**计算机系统的各个组成部分及其工作机制**，体系架构研究**计算机指令集、I/O机制、寻址技术**等等，对理解计算机的组成原理和运行机制，计算机硬件对编译器和操作系统的支持等具有重要意义。
2. **计算机的主要部件**：主板、CPU、内存、硬盘、显卡、显示器、鼠标、键盘
3. **EDSAC**：按课件口径，这是第一台存储程序计算机。它含有约 3000 个真空管，排列在 12 个机架上，占地约 $5\times4\ \text{m}^2$，功耗约 12 kW，包含运算器、控制器、存储器、输入和输出，速度约为每秒 650 条指令。
4. 随着集成电路集成度的不断提高，可以在同样大小的芯片中塞入更多的元器件，计算机性能越来越好、容量越来越大、体积越来越小。
5. **摩尔定律**：芯片上晶体管数量每隔一段时间翻一倍，处理器性能越来越强，越来越小。
6. **课程目标**：研究CPU和存储器的瓶颈、CPU和I/O设备的问题、解释计算机体系结构与计算机设计中的一些现象、研究如何提高性能、研究如何通过其他技术提高执行速度。
## 二、为什么要学习计算机组织与架构

1. 课程的两条设计主线：**平衡**（Balance） 、**并行**(Parallel)。
2. 目的：了解计算机设计与组织问题，也就是计算机硬件，使我们能够分析指令设计、指令在处理器中的实现以及性能问题之间的内在关系。

### 指令执行示例：`ADD R1, R2`

指令含义为 $R1\leftarrow R1+R2$。一种可能的内部微操作过程是：

1. $ALU1\leftarrow[R1]$
2. $ALU2\leftarrow[R2]$
3. $ALU3\leftarrow ALU1+ALU2$
4. $R1\leftarrow[ALU3]$

若每个微操作使用 1 个时钟周期，则共需 4 个周期，其中 3 个周期用于数据传送，即数据传送占 $75\%$。

> [!tip] 由此得到的设计启示
> 单总线一次只能完成一次传送，容易形成瓶颈；双总线或多总线可提高并行传送能力，但会增加硬件成本与控制复杂度。

### CPU—内存瓶颈

课件示例中，主频高于 1 GHz 的 CPU 内部传送可能不到 1 ns，而主存访问约需 40～60 ns，因此 CPU 可能等待几十个时钟周期。典型缓解方法是：

- 在 CPU 与主存之间加入 Cache；
- 提高一次传输的数据位数和总线带宽；
- 使用分层存储结构；
- 采用流水线，让多条指令的不同阶段重叠执行。

## 三、组织（Organization）与架构（Architecture）
### （1）架构

**定义**：**对计算机系统功能和接口的抽象定义**，关注“系统应该提供哪些能力”，以及“软件如何与硬件交互”。它是硬件与软件之间的“契约”，决定了程序员需要了解的核心属性。
**主要内容**：
- 指令集及指令格式；
- 数据类型及表示方法；
- 寻址方式；
- 寄存器数量与功能；
- 中断机制；
- I/O 机制；
- 内存模型与地址空间。
例子：“xx支持 32 位整数加法指令，并提供 16 个通用寄存器。”
### （2）组织
**定义**：**针对架构规定的物理或逻辑实现细节**，确定“如何高效实现架构定义的功能”。它是架构的“底层实现”，通常对程序员透明（不影响程序逻辑）。
**主要内容**
- 数据通路设计；
- ALU、寄存器和存储器之间的连接；
- 单总线还是多总线；
- 控制器采用硬布线还是微程序控制；
- Cache 的大小和层级；
- 存储器速度与带宽；
- 时钟频率；
- 指令执行的微操作和时序。

例如，架构规定支持 32 位加法，组织层面需要确定：

- 使用串行进位还是先行进位加法器；
- 操作数如何从寄存器送入加法器；
- 运算结果如何写回；
- 整个过程需要几个时钟周期。
### （3）区别
| 维度   | 计算机架构 Architecture | 计算机组织 Organization  |
| ---- | ------------------ | ------------------- |
| 本质   | 抽象规范               | 具体实现                |
| 核心问题 | **做什么**            | **怎么做**             |
| 对程序员 | 可见，影响程序编写          | 通常透明，不改变程序逻辑        |
| 主要内容 | 指令集、数据类型、寄存器、寻址方式  | 数据通路、电路、总线、Cache、时序 |
| 稳定性  | 相对稳定，强调兼容性         | 随技术快速变化             |
| 示例   | 支持某条 ADD 指令        | ADD 指令采用几条总线、几个周期实现 |
 **同一架构可以有不同组织**：

- 高通和苹果处理器可以采用相同或兼容的 ARM 指令集；
- 但其内部流水线、Cache、总线、执行单元可能完全不同；
- 因此可以运行兼容代码，但性能和功耗存在差异。

x86、IBM System/370 等系列也体现了这一特点：

- 同一系列保持基本架构一致；
- 不同型号采用不同组织；
- 从而在保持代码兼容的同时提供不同价格与性能。
### （4）总结

**架构 = 做什么，是软件可见的接口。**  
**组织 = 怎么做，是对架构的具体实现。**

### （5）计算机组织与硬件的关系
| 项目   | 计算机组织        | 硬件                |
| ---- | ------------ | ----------------- |
| 本质   | 设计蓝图和调度逻辑    | 物理载体和实现基础         |
| 作用   | 决定各硬件如何组合、交互 | 提供 ALU、寄存器、存储器等部件 |
| 依赖关系 | 必须依据硬件特性设计   | 必须经过组织和调度才能形成系统功能 |
可概括为：**架构定义目标，组织给出方案，硬件完成落地。**
## 四、结构与功能
### 1. 基本概念

#### 结构（Structure）

描述硬件部件的：

- 构成方式；
- 连接关系；
- 层次划分。

即：==有什么、怎么连接==。

#### 功能（Function）

描述计算机通过这些结构实现的能力，即：==能做什么==。
### 2. 计算机的四类基本功能

所有计算机功能都可以归纳为：

1. 数据处理（Data Processing）
    - 算术运算；
    - 逻辑运算。
2. 数据存储（Data Storage）
    - 临时保存；
    - 长期保存。
3. 数据移动（Data Movement）
    - 部件之间传送数据；
    - 与外部设备交换数据。
4. 控制（Control）
    - 决定操作顺序；
    - 协调各部件同步工作。
### 3. 自顶向下的层次结构
```TEXT
Computer
├── CPU
│   ├── ALU
│   ├── Control Unit
│   │   ├── Sequencing Logic
│   │   ├── Registers and Decoders
│   │   └── Control Memory（微程序控制器）
│   ├── Registers
│   └── Internal Interconnection
├── Main Memory
├── Input / Output
└── System Interconnection
```
#### 计算机顶层结构

- CPU；
- 主存；
- I/O；
- 系统互连。
#### CPU 内部结构

- 算术逻辑单元 ALU；
- 控制单元 CU；
- 寄存器；
- CPU 内部互连。
### 4. 结构与功能的双向关系

#### 结构决定功能

- 只有整数 ALU，则不能直接完成浮点运算；
- 增加 FPU，才能高效支持浮点功能；
- 32 位 ALU 与 64 位 ALU 的处理能力不同；
- 加入 Cache 后，可以降低 CPU 等待主存的时间；
- 没有 I/O 接口，就无法与键盘、显示器等外设交互。

#### 功能需求推动结构升级

- 并行处理需求：单核 → 多核；
- 高速存储需求：HDD → SSD；
- AI 矩阵运算需求：GPU 中加入张量核心。

### 5. 总结

**结构是功能的载体，功能是结构设计的目标**
## 五、计算机发展史

### 2. 电子器件与计算机“代”的划分

**注**：计算机的“代”主要依据==**所使用的基本电子器件和集成电路集成度**==划分

| 阶段          | 时间（课件口径）  | 主导技术                |

### 3. 存储程序思想与冯·诺依曼机

#### （1）ENIAC 的局限

ENIAC 于 1943 年开始研制，1946 年完成，最初用于弹道计算。它使用十进制而非二进制，程序主要通过重新接线和设置开关来改变，修改程序可能需要数天。

#### （2）存储程序思想

1945 年，冯·诺依曼在 EDVAC 报告中系统阐述了存储程序思想。其核心特征是：

1. 指令和数据共同存放在主存中；
2. 指令和数据均采用二进制表示；
3. 通过地址选择存储器中的指令或数据；
4. ALU 完成基本运算；
5. 控制单元按顺序取指并控制执行。

#### （3）IAS 计算机

IAS 计算机于 1946 年开始设计，1952 年完成，是冯·诺依曼机的典型实现。它包含 ALU、主存、控制单元、输入设备和输出设备五个功能部件。

- 主存容量：$1000\times40$ 位字；
- 一个 40 位字可存放一个带符号数：1 位符号位 + 39 位数值；
- 一个 40 位字也可存放两条 20 位指令；
- 每条指令由 8 位操作码和 12 位地址组成。

| 缩写 | 名称 | 作用 |
| --- | --- | --- |
| MAR | Memory Address Register | 保存要访问的存储单元地址 |
| MBR | Memory Buffer Register | 暂存从存储器读出或准备写入的数据 |
| IR | Instruction Register | 保存当前正在执行的指令操作码 |
| IBR | Instruction Buffer Register | 暂存同一存储字中的下一条指令 |
| PC | Program Counter | 保存下一条待取指令的地址 |
| AC | Accumulator | 保存 ALU 操作数和结果 |
| MQ | Multiplier Quotient Register | 保存乘数或商等数据 |

```text
PC 给出地址 → 从主存取指 → IR/IBR 保存指令
→ 控制单元译码 → ALU/主存/I/O 执行 → PC 更新
```

IAS 支持数据传送、算术运算、无条件转移、条件转移和地址修改等指令类型，已经具备现代通用计算机的基本轮廓。

### 4. 从真空管到晶体管
晶体管相比真空管：

- 体积更小；
- 成本更低；
- 发热更少；
- 可靠性更高。

晶体管使计算机能够拥有：

- 更复杂的 ALU 和控制器；
- 更强的运算能力；
- 更丰富的指令集；
- 高级语言和系统软件。

代表机器：IBM 7094。

#### IBM 7094 的 I/O 组织

- 数据通道（Data Channel）
    
    - 独立的 I/O 模块；
    - 拥有自己的处理器和指令集；
    - 可分担 CPU 的 I/O 工作。
- 多路复用器（Multiplexer）
    
    - CPU、主存和多个数据通道的中心连接点。

### 5. 集成电路与微电子

分立晶体管的缺点：

- 元件需要分别制造；
- 电路板连接复杂；
- 成本高、可靠性受互连影响。

1958 年集成电路出现后，可将：

- 晶体管；
- 电阻；
- 导体；
- 互连线路；

集中制造在一小块硅芯片上。

从微电子角度看，计算机由三部分构成：

1. 逻辑门；
2. 存储单元；
3. 部件之间的互连。

### 6. 摩尔定律（Moore's Law）

内容：单个芯片上的晶体管数量大约每 18 个月翻一倍。

它是一条经验规律，而非物理定律。

提高集成度通常会带来：

- 单位功能成本降低；
- 电路路径缩短，速度提高；
- 体积减小；
- 同等功能下功耗和散热需求降低；
- 外部互连减少，可靠性提高；
- 可在一块芯片上集成更复杂的功能。

### 7. 计算机系列与兼容性
#### （1）计算机系列（Computer Family）

同一系列中的计算机通常具有：

- 相同或相似的指令集；
- 相同或相似的操作系统；
- 不同的速度；
- 不同的内存容量；
- 不同数量的 I/O 接口；
- 不同的价格。

本质上：

> **系列机具有相同或兼容的架构，但采用不同的组织实现。**

#### （2）IBM System/360

1964 年推出，是业界第一个经过规划的计算机系列。

特点：

- 覆盖较大的性能和价格范围；
- 同一程序可在不同型号上运行；
- 型号之间主要表现为执行速度和配置不同；
- 用户可以从低端型号升级到高端型号。

#### （3）DEC PDP-8

特点：

- 体积小；
- 成本低；
- 适合被其他厂商集成到完整系统中，促进 OEM 模式；
- 后期采用具有 96 根信号线的 Omnibus 总线；
- CPU、主存、I/O 模块都可插接到总线上，配置灵活。

#### （4）向后兼容

Backward Compatibility 指：

> **新一代系统能够继续运行旧一代系统的软件或机器代码。**

x86 长期成功的重要原因之一，就是在演进时保持较强的向后兼容性。

### 8. 存储器的发展
#### （1）磁芯存储器（Core Memory）

20 世纪 50～60 年代广泛使用。

工作原理：

- 每个铁氧体磁环表示一位；
- 顺时针或逆时针磁化分别表示 0 或 1；
- 断电后仍能保持状态。

特点：

- 非易失；
- 访问时间约 1 μs；
- 价格昂贵；
- 读取具有破坏性，读取后必须重新写回。

#### （2）半导体存储器

1970 年前后出现：
- 密度更高；
- 速度约 70 ns，远快于磁芯；
- 读取非破坏性；
- 初期价格更高。

1974 年：
- 半导体存储器每比特价格低于磁芯存储器；
- 此后容量持续增加、单位成本持续下降；
- 最终取代磁芯存储器。
### 9. 微处理器的发展

微处理器将 CPU 的主要部件集成到单个芯片上。

| 时间   | 处理器        | 主要意义                    |
| ---- | ---------- | ----------------------- |
| 1971 | Intel 4004 | 第一款微处理器，4 位，面向专用应用      |
| 1972 | Intel 8008 | 早期 8 位微处理器，面向专用应用       |
| 1974 | Intel 8080 | Intel 第一款通用微处理器，8 位数据通路 |

其发展基础是：
- 集成度不断提高；
- 单芯片可以容纳更多功能；
- 处理器速度、指令集和寻址能力不断增强。

## 六、x86 和 ARM 处理器家族

### 1. x86
#### （1）演化脉络
| 处理器             | 主要特征                               |
| --------------- | ---------------------------------- |
| 8086            | 16 位，5 MHz，约 29000 个晶体管；采用指令预取队列   |
| 8088            | 内部结构接近 8086，外部总线为 8 位；用于第一代 IBM PC |
| 80286           | 可寻址约 16 MB 内存                      |
| 80386           | 32 位，增强多任务支持                       |
| 80486           | 片上 Cache、指令流水线、内置数学协处理器            |
| Pentium         | 超标量，可并行执行多条指令                      |
| Pentium Pro     | 寄存器重命名、分支预测、数据流分析、推测执行             |
| Pentium II      | MMX，多媒体处理增强                        |
| Pentium III     | 增加面向 3D 图形的浮点指令                    |
| Pentium 4       | 进一步增强浮点和多媒体能力                      |
| Core            | 进入双核时代                             |
| Core 2          | 64 位架构                             |
| Core 2 Quad     | 单芯片四核                              |
| Core i3/i5/i7 等 | 持续提高多核、Cache、流水线和能效                |
#### （2）x86 的核心特点
- 在桌面和服务器领域长期占重要地位；
- 指令集持续扩展；
- 强调向后兼容；
- 架构相对稳定，但内部组织不断变化。

x86 的发展很好地说明：

>  **架构可以保持兼容，组织可以持续优化。**

### 2. ARM

ARM 原意为 Advanced RISC Machine。

#### （1）主要特点
- 采用 RISC 思想；
- 高性能、低功耗；
- ARM 公司主要向芯片制造商授权架构和处理器 IP；
- 广泛用于移动设备、嵌入式系统和物联网设备。

#### （2）Cortex 系列
|系列|定位|典型应用|
|---|---|---|
|Cortex-A|Application|智能手机、电子书、数字电视、网关|
|Cortex-R|Real-time|汽车制动、存储控制器、网络与打印设备|
|Cortex-M|Microcontroller|物联网、无线传感器、汽车电子|

### 3. 两者对比

| 维度      | x86        | ARM           |
| ------- | ---------- | ------------- |
| 传统指令集风格 | CISC       | RISC          |
| 核心优势    | 软件生态和向后兼容  | 低功耗、可授权、易于定制  |
| 传统应用    | PC、服务器     | 移动设备、嵌入式系统    |
| 演化方式    | 在兼容基础上不断扩展 | 不同厂商可采用不同组织实现 |

## 七、嵌入式系统

### 1. 定义
嵌入式系统是：

> 为一个或少数专用功能设计，并通常具有实时约束的专用计算机系统。

特点：

- 通常是完整设备的一部分；
- 与硬件、机械部件共同工作；
- 复杂度可从单片微控制器到多处理器系统；
- 强调满足具体场景，而不是通用计算能力。
### 2. 设计要求

- 尺寸与成本限制；
- 安全性；
- 可靠性；
- 实时性；
- 灵活性与可扩展性；
- 法规合规性；
- 生命周期；
- 温度、振动等环境条件；
- 静态或动态负载；
- 计算密集型或 I/O 密集型；
- 低功耗。

## 八、云计算

### 1. 定义
狭义上，云计算是一种通过网络提供资源的方式：
- 随时获取资源；
- 按需使用；
- 动态扩展；
- 按使用量付费。

广义上，云计算是：

> 将大量计算、存储和网络资源汇集为共享资源池，并通过软件进行自动化管理和服务化交付。

### 2. 主要特点

- 虚拟化；
- 动态可扩展；
- 按需请求和使用；
- 灵活性高；
- 可靠性高；
- 性价比高。

### 3. 分类

#### 按使用范围

- 公有云；
- 私有云。
#### 按用途

- 存储云；
- 金融云；
- 教育云；
- 医疗云。

### 4. 服务模型

| 模型   | 提供内容             | 简单记忆  |
| ---- | ---------------- | ----- |
| IaaS | 虚拟机、存储、网络等基础设施   | 租硬件资源 |
| PaaS | 开发、测试、部署和管理应用的平台 | 租开发平台 |
| SaaS | 可直接通过网络使用的应用软件   | 直接用软件 |
### 5. 核心技术

- 虚拟化；
- 分布式文件系统；
- 分布式数据库；
- 资源管理与调度；
- 能耗管理；
- 网络与信息安全。

## 九、一页复习

> [!summary] 必背结论
> - **架构 = 做什么；组织 = 怎么做；硬件 = 用什么实现。**
> - **结构是功能的载体，功能是结构设计的目标。**
> - 计算机的四类基本功能：数据处理、数据存储、数据移动、控制。
> - 计算机“代”的划分依据：基本电子器件与集成度。
> - 存储程序思想：指令与数据同存于主存，按地址访问，控制器按取指—执行循环工作。
> - 两条性能设计主线：平衡与并行。
