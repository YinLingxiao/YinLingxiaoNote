# Lesson 03 栈与队列

## 二、栈：只能在同一端操作的线性表

### 2.1 基本概念

- **栈顶（Top）**：允许插入和删除的一端。
- **栈底（Bottom）**：另一端。
- **入栈（Push）**：把元素放到栈顶。
- **出栈（Pop）**：取出并删除栈顶元素。
- **取栈顶（GetTop / Peek）**：读取栈顶，栈不改变。
- **LIFO**：Last In, First Out，后进先出；也称 FILO，先进后出。

```text
依次 Push(A), Push(B), Push(C)

栈底 [ A | B | C ] 栈顶

连续 Pop()：C → B → A
```

### 2.2 ADT 的基本操作

| 操作 | 含义 | 前提 / 注意 |
| :--- | :--- | :--- |
| `InitStack(S)` | 初始化空栈 | 建立合法的初始状态 |
| `DestroyStack(S)` | 销毁栈 | 释放资源 |
| `ClearStack(S)` | 清空元素 | 栈仍保留，可继续使用 |
| `StackEmpty(S)` | 判断是否为空 | 返回布尔结果 |
| `StackLength(S)` | 求元素个数 | 与容量不同 |
| `Push(S, e)` | 入栈 | 固定容量实现要检查栈满 |
| `Pop(S, e)` | 删除栈顶，并通过 `e` 返回值 | 必须非空 |
| `GetTop(S, e)` | 读取栈顶 | 必须非空，不删除 |
| `StackTraverse(S, visit)` | 遍历元素 | 访问顺序应由接口约定 |

> [!warning] 空栈也属于栈的合法状态
> 讲义 p.6 的数据对象写成 `n ≥ 1`，但后续初始化、判空等操作都需要空栈。整理时应允许 **`n ≥ 0`**。

### 2.3 合法出栈序列

输入顺序固定时，可以在入栈过程中穿插出栈，但不能改变输入的先后关系。

输入 `A, B, C`，合法输出共 5 种：

```text
ABC    ACB    BAC    BCA    CBA
```

`CAB` 不合法：为了先弹出 C，A、B 必须已经入栈；弹出 C 后，B 压在 A 上面，下一次只能先弹 B。

**通用判断方法：模拟栈。** 对每一个期望输出的元素，若当前栈顶不是它，就继续按输入顺序入栈；如果输入用完仍无法得到目标栈顶，该输出序列不合法。

> [!tip] 禁止出现的相对顺序
> 若输入中 `aᵢ` 在 `aⱼ` 前、`aⱼ` 在 `aₖ` 前，即 `i < j < k`，输出不能出现 `aₖ → aᵢ → aⱼ` 的相对顺序。
> 原因是弹出 `aₖ` 时，尚未弹出的 `aⱼ` 必然挡在 `aᵢ` 上面。

**补充：** n 个不同元素依次入栈、允许交错出栈、栈容量足够时，合法出栈排列数为 Catalan 数：

$$C_n=\frac{1}{n+1}\binom{2n}{n}$$

所以 `C₃ = 5`、`C₄ = 14`，并不是所有 `n!` 种排列都合法。

## 三、顺序栈：用连续空间存储

### 3.1 指针约定是关键

讲义使用动态数组：

```cpp
struct SqStack {
    int* base;     // 数组起始地址
    int* top;      // 栈顶元素的下一个位置
    int capacity;  // 已分配容量，讲义称 stacksize
};
```

```text
下标       0     1     2     3     4
数组     [ A ] [ B ] [ C ] [   ] [   ]
           ↑                 ↑
          base              top
实际栈顶元素：*(top - 1)
```

| 状态 / 操作 | 表达式 |
| :--- | :--- |
| 空栈 | `top == base` |
| 当前长度 | `top - base` |
| 存储空间已满 | `top - base == capacity` |
| 读取栈顶 | `*(top - 1)`，先检查非空 |
| 入栈 | `*top++ = e`，先确保容量足够 |
| 出栈 | `e = *--top`，先检查非空 |

**记忆：入栈先放后移，出栈先退后取。**

讲义图中的 `top = M` 是下标意义；如果 `top` 是指针，应理解为 `top = base + M`。

### 3.2 入栈、出栈与扩容

整理后的核心代码（使用 `malloc/realloc/free` 管理同一块内存）：

```cpp
#include <cstdlib>

bool Push(SqStack& s, int e) {
    if (s.top - s.base == s.capacity) {
        int oldSize = s.capacity;
        int* p = static_cast<int*>(
            std::realloc(s.base, (oldSize + 10) * sizeof(int)));
        if (!p) return false;
        s.base = p;
        s.top = s.base + oldSize;
        s.capacity = oldSize + 10;
    }
    *s.top++ = e;
    return true;
}

bool Pop(SqStack& s, int& e) {
    if (s.top == s.base) return false;
    e = *--s.top;
    return true;
}
```

初始化时分配数组，令 `top = base`；清空时令 `top = base`；销毁时 `free(base)`，并把两个指针设为空、容量置 0。

> [!warning] 扩容后必须重建 top
> `realloc` 可能改变整块内存的地址，旧 `top` 可能失效。讲义在“满栈扩容”的前提下，用 `top = base + 旧容量` 恢复位置。
> 整理代码用临时指针接收 `realloc` 结果，以免分配失败时丢失旧内存地址。

### 3.3 时间复杂度

- 不扩容的 Push、Pop、GetTop：`O(1)`。
- 一次需要搬移内存的扩容：最坏 `O(n)`。
- **补充：**讲义每次只增加固定的 10 个位置，不能因此直接声称 Push 均摊 `O(1)`。连续插入 n 个元素，在反复搬移的最坏情形下总成本可达 `O(n²)`；采用倍增等几何扩容策略，才可实现 Push 均摊 `O(1)`。

## 四、链栈：以链表头作为栈顶

讲义使用**不带头结点**的单链表，`top` 直接指向第一个数据结点。

```text
top → C → B → A → nullptr
      栈顶      栈底
```

选择表头作为栈顶，是因为单链表的头插、头删都能直接完成；若在表尾删除，通常还要遍历查找前驱。

```cpp
struct SNode {
    int data;
    SNode* next;
};

// 初始化：SNode* top = nullptr;
void Push(SNode*& top, int e) {
    top = new SNode{e, top};
}

bool Pop(SNode*& top, int& e) {
    if (!top) return false;
    SNode* p = top;
    e = p->data;
    top = p->next;
    delete p;
    return true;
}
```

- 判空：`top == nullptr`。
- 入栈：新结点连接旧栈顶，再更新 `top`。
- 出栈：保存旧结点，栈顶后移，再释放旧结点。
- Push、Pop、GetTop 在通常的结点分配成本模型下都是 `O(1)`。
- 不需要预先给定数组容量，但每个结点需要额外存储指针，也可能发生内存分配失败。

> [!note] 内存管理约定
> 上面的链栈示例采用 `new/delete`，讲义采用 `malloc/free`。同一结点的申请与释放必须配套。

## 五、栈的四类直接应用

### 5.1 括号匹配（p.26–28）

核心：**最后出现的、尚未匹配的左括号，应该最先得到匹配。**

1. 从左到右扫描。
2. 遇到 `(`、`[`：入栈。
3. 遇到 `)`、`]`：栈必须非空，弹出栈顶并检查类型。
4. 扫描结束：栈必须为空。

```text
输入 [ ( ) ]
[ ：栈为 [
( ：栈为 [ (
) ：弹出 (，匹配
] ：弹出 [，匹配
结束为空：合法
```

三种失败情况：右括号过多导致空栈、左右括号类型不匹配、结束后还剩左括号。`[(])` 虽然各类括号数量相等，仍不合法。

时间 `O(n)`，最坏辅助空间 `O(n)`。补充：花括号可按相同规则加入。

### 5.2 数制转换（p.29–30）

十进制非负整数 N 转 b 进制：反复除以 b，把余数入栈，再依次出栈。

```text
1348 ÷ 8 = 168 ... 4
 168 ÷ 8 =  21 ... 0
  21 ÷ 8 =   2 ... 5
   2 ÷ 8 =   0 ... 2

余数产生：4、0、5、2
出栈输出：2、5、0、4
所以 (1348)₁₀ = (2504)₈
```

原因：余数按低位到高位产生，输出需要从高位到低位。

**边界补充：**N 为 0 时应直接输出 `0`；负数先处理符号；b 大于 10 时需用字母等表示数码。对 N > 0，操作次数与位数成正比，为 `O(log_b N)`。

### 5.3 后缀表达式求值（p.31–32）

| 表达形式 | 示例 | 含义 |
| :--- | :--- | :--- |
| 中缀 Infix | `(5 + 4) * 2` | 运算符在操作数之间 |
| 后缀 Postfix | `5 4 + 2 *` | 运算符在操作数之后 |

后缀表达式通过排列顺序表达计算关系，不需要括号。

算法：遇到操作数就入栈；遇到二元运算符就弹出两项，计算后把结果入栈。

> [!warning] 左右操作数顺序
> **先弹出的为右操作数 b，后弹出的为左操作数 a，计算 a op b。**
> 如 `8 2 -` 应算 `8 - 2 = 6`，不能算成 `2 - 8`。

```text
6 5 + 8 *

读 6： [6]
读 5： [6, 5]
读 +： [11]
读 8： [11, 8]
读 *： [88]
```

补充校验：每个二元运算符都需要至少两个操作数；最后必须恰好剩一个结果；还应处理除零等错误。多位数应按完整 token 读取，而不是把每个数字字符分别入栈。时间 `O(n)`，最坏辅助空间 `O(n)`，n 为 token 数。

### 5.4 中缀转后缀（p.33–36）

使用**运算符栈**，操作数直接进入输出序列。对讲义中的二元 `+ - * /`，乘除优先于加减，且都为左结合。

| 读到的 token | 动作 |
| :--- | :--- |
| 操作数 | 直接输出 |
| `(` | 直接入栈 |
| `)` | 弹出并输出，直到遇到 `(`；弹出并丢弃 `(` |
| 普通运算符 | 栈顶不是 `(` 且优先级大于或等于当前运算符时，持续弹出并输出；再压入当前运算符 |
| 输入结束 | 把剩余运算符依次弹出并输出；若仍有括号则表达式有误 |

**括号是分组边界，不应把它当作普通运算符统一处理。** 读到左括号直接入栈，读到右括号专门匹配。

示例：`A * B + C * D`

| 当前输入 | 运算符栈（左为栈底） | 已输出 |
| :--- | :--- | :--- |
| A | 空 | A |
| * | * | A |
| B | * | A B |
| + | + | A B * |
| C | + | A B * C |
| * | + * | A B * C |
| D | + * | A B * C D |
| 结束 | 空 | A B * C D * + |

其他例子：

```text
(A + B) * C          → A B + C *
a + b*c + (d*e+f)*g  → a b c * + d e * f + g * +
a - b - c            → a b - c -
```

最后一例说明：同优先级的左结合运算符也要弹栈。补充：如果扩展到右结合运算符（如数学中的幂），相同优先级时的规则需要调整；一元负号也需另行定义。

每个 token 至多入栈、出栈一次，时间 `O(n)`，最坏辅助空间 `O(n)`。

## 六、函数调用与递归

### 6.1 为什么函数调用需要栈？（p.37–39）

调用新函数时，需要保存调用者的返回位置、局部状态等；被调用者结束后，先恢复最近暂停的调用者，因此符合后进先出。

```text
main 调用 f，f 先调用 g，再调用 h

调用栈（左为栈底）：
[main]
[main, f]
[main, f, g]
[main, f]       ← g 返回
[main, f, h]
[main, f]       ← h 返回
[main]         ← f 返回
```

每次调用有自己的栈帧。递归中同一个函数的不同调用，也要分别保存参数和局部状态。

### 6.2 递归的两个必要部分（p.40–47）

- **基本情况 / 终止条件（Base case）**：能直接求解，不再递归。
- **递归步骤（Recursive case）**：把问题化成更小的同类问题，保证朝终止条件推进。

设计顺序：确定如何分解 → 找终止条件 → 写分支 → 检查所有递归路径是否终止及边界是否合理。

### 6.3 阶乘

$$n!=\begin{cases}1,&n=0\\n(n-1)!,&n\ge1\end{cases}$$

```cpp
// 前提：n >= 0，且结果不超过整数类型范围。
long long Factorial(int n) {
    if (n == 0) return 1;
    return n * Factorial(n - 1);
}
```

```text
Factorial(3)
→ 3 × Factorial(2)
→ 3 × 2 × Factorial(1)
→ 3 × 2 × 1 × Factorial(0)
→ 3 × 2 × 1 × 1 = 6
```

补充：通常分析下时间 `O(n)`，调用栈空间 `O(n)`；迭代实现只需 `O(1)` 辅助空间。负数输入不能直接套用该递归，否则无法到达终止条件。

### 6.4 递归寻找单链表末尾结点

讲义 p.42：若当前结点的 `next` 为空，则当前结点是最后一个；否则递归处理后继。

补充边界：空链表应先判空；若链表带头结点，应从首个数据结点开始。对含 n 个数据结点的非空单链表，时间 `O(n)`、递归栈空间 `O(n)`；迭代可降低辅助空间。

### 6.5 汉诺塔（p.43–44）

规则：每次只移动一个圆盘；可使用 A、B、C 三根柱；大盘不能压在小盘上。

把 n 个盘从 A 移到 C，借助 B：

1. 将上面的 n−1 个盘从 A 移到 B，借助 C。
2. 将最大的盘从 A 移到 C。
3. 将 B 上的 n−1 个盘移到 C，借助 A。

**补充推导：**令 `T(0)=0`，则

$$T(n)=2T(n-1)+1=2^n-1$$

时间 `O(2^n)`，最大递归深度为 `O(n)`。**总调用次数与最大递归深度不是一回事。**

## 七、队列：一端插入、另一端删除

### 7.1 基本概念（p.49–52）

- **FIFO**：First In, First Out，先进先出。
- **队头 Front**：删除的一端。
- **队尾 Rear**：插入的一端。
- **EnQueue**：入队。
- **DeQueue**：出队。

```text
出队 ← [ A | B | C ] ← 入队
        队头      队尾

A、B、C 依次入队，之后连续出队得到 A、B、C。
```

> [!tip] 先确认 front 和 rear 的具体含义
> 循环队列中的 `front` 指向队头元素，`rear` 指向队尾之后的空位。
> 本讲链队列带头结点，`front` 指向头结点，`rear` 指向最后一个数据结点。两种实现不能混用指针语义。

### 7.2 链队列（p.54–58）

```text
front
  ↓
[头结点] → A → B → C → nullptr
                    ↑
                   rear
```

**状态约定：**

- 初始化：申请头结点，`front = rear`，`front->next = nullptr`。
- 判空：`front == rear`。
- 第一个数据结点：`front->next`。
- 入队：把新结点接在 `rear` 后面，再移动 `rear`。
- 出队：删除 `front->next`，保留头结点。

```cpp
struct QNode {
    int data;
    QNode* next;
};
struct LinkQueue {
    QNode* front;
    QNode* rear;
};

void EnQueue(LinkQueue& q, int e) {
    QNode* p = new QNode{e, nullptr};
    q.rear->next = p;
    q.rear = p;
}

bool DeQueue(LinkQueue& q, int& e) {
    if (q.front == q.rear) return false;
    QNode* p = q.front->next;
    e = p->data;
    q.front->next = p->next;
    if (q.rear == p) q.rear = q.front;
    delete p;
    return true;
}
```

> [!warning] 删除最后一个元素后必须更新 rear
> 如果不执行 `rear = front`，`rear` 就会指向已释放的结点，下次入队会访问无效内存。

链队列入队、出队均为 `O(1)`；销毁时需释放全部数据结点和头结点，为 `O(n)`，之后将两个指针置空。

## 八、顺序队列与循环队列

### 8.1 假溢出（p.60–62）

非循环数组实现中，若出队只增加 `front`、入队只增加 `rear`，数组前面释放的空间就无法直接再利用。

```text
容量 M = 6
下标      0    1    2    3    4    5
数组    [空] [空] [空] [D]  [E]  [F]
                        ↑              ↑
                     front=3         rear=6
```

此时还有 3 个空位，但 `rear` 已到数组末尾，无法按原来的方式继续入队，称为**假溢出**。

解决思路：移动剩余元素到数组前端，或把数组作为循环空间使用。讲义 p.80–82 还展示了出队后整体前移的实现，其出队成本为 `O(n)`。

### 8.2 循环队列的下标规则（p.63–73）

数组下标范围 `0 … M−1`，每次前进一步都用取模绕回开头：

$$\text{next}(i)=(i+1)\bmod M$$

例如 M = 6，`5 → 0`。

**本节统一采用“牺牲一个存储单元”的约定：**

- `front` 指向队头元素。
- `rear` 指向队尾元素的下一个位置。
- 实际元素沿着 `front` 到 `rear` 的循环方向排列，包含 front，不包含 rear。

### 8.3 空、满、长度：必须熟记

| 项目 | 公式 |
| :--- | :--- |
| 初始化 | `front = rear = 0` |
| 空队列 | `front == rear` |
| 满队列 | `(rear + 1) % M == front` |
| 队列长度 | `(rear - front + M) % M` |
| 最大可存元素数 | `M - 1` |

为什么牺牲一个单元？如果 M 个位置全部利用，绕一圈后 `rear == front`，空和满会出现相同状态。预留一个空位，就能让满队列在 rear 的下一位置到达 front 时停止。

补充：也可以增加元素计数 `count` 或额外状态标志区分空满，并利用全部 M 个单元；这时判满规则与容量解释必须相应改变。

### 8.4 核心代码

```cpp
constexpr int M = 6;
struct SqQueue {
    int data[M];
    int front = 0;
    int rear = 0;
};

bool EnQueue(SqQueue& q, int e) {
    if ((q.rear + 1) % M == q.front) return false;
    q.data[q.rear] = e;
    q.rear = (q.rear + 1) % M;
    return true;
}

bool DeQueue(SqQueue& q, int& e) {
    if (q.front == q.rear) return false;
    e = q.data[q.front];
    q.front = (q.front + 1) % M;
    return true;
}
```

入队、出队都不需要搬移其他元素，均为 `O(1)`。

### 8.5 带回绕的完整例子

M = 6，最多存 5 个元素：

| 操作 | front | rear | 逻辑队列（队头 → 队尾） | 长度 |
| :--- | ---: | ---: | :--- | ---: |
| 初始化 | 0 | 0 | 空 | 0 |
| A、B、C、D 入队 | 0 | 4 | A B C D | 4 |
| 出队两次 | 2 | 4 | C D | 2 |
| E 入队 | 2 | 5 | C D E | 3 |
| F 入队 | 2 | 0 | C D E F | 4 |
| G 入队 | 2 | 1 | C D E F G | 5 |

最后 `(1+1)%6 == 2`，队列已满。实际数组为：

```text
下标  0   1   2   3   4   5
     [G] [空] [C] [D] [E] [F]
          ↑    ↑
         rear front
```

**逻辑顺序是 C、D、E、F、G，并不是数组下标从 0 开始的顺序。** 已出队位置可能还残留旧值，但不再属于队列。

### 8.6 动态循环队列扩容（p.74–77）

讲义动态版本以 `queuesize` 记录当前分配容量，仍采用保留一个空位的方案。

难点：改变容量后，取模基数也改变；若有效元素跨越了数组末尾，仅 `realloc` 并增加容量会破坏原来的循环顺序。

讲义方案：设旧容量 M、增加 Δ 个单元。

1. 扩展数组空间。
2. 若 `front > rear`，说明队列已回绕，把高端区间 `[front, M−1]` 的元素整体右移 Δ 位。
3. 为避免覆盖，从高下标向低下标移动，并令 `front += Δ`。
4. 更新容量，然后按新的取模基数入队。

例：M = 6，Δ = 2，`front=4, rear=3`：

```text
扩容前：[C, D, E, 空, A, B]       逻辑顺序 A B C D E
扩容后：[C, D, E, 空, 空, 空, A, B]
                               front=6，rear=3
```

沿新容量 8 循环访问得到下标 `6 → 7 → 0 → 1 → 2`，逻辑顺序保持不变。

**补充：更容易实现的另一种办法**是另申请新数组，依次复制 `old[(front+i)%M]` 到 `new[i]`，最后设置 `front=0, rear=元素个数`。单次扩容最坏 `O(n)`；普通不扩容的入队仍为 `O(1)`。

## 九、对比与复杂度速查

### 9.1 栈与队列

| 对比 | 栈 Stack | 队列 Queue |
| :--- | :--- | :--- |
| 操作规则 | LIFO，后进先出 | FIFO，先进先出 |
| 插入位置 | 栈顶 | 队尾 |
| 删除位置 | 栈顶 | 队头 |
| 典型用途 | 括号、表达式、调用栈、递归 | 打印任务、网络缓冲、操作系统中的排队场景 |

### 9.2 实现方式

| 实现 | 插入 | 删除 | 主要特点 |
| :--- | :--- | :--- | :--- |
| 顺序栈 | 普通操作 O(1)，扩容最坏 O(n) | O(1) | 连续存储，需管理容量 |
| 链栈 | O(1) | O(1) | 头插头删，每结点带指针 |
| 链队列 | O(1) | O(1) | 队头删除、队尾插入，注意最后一结点 |
| 固定容量循环队列 | O(1) | O(1) | 取模回绕，先明确空满方案 |
| 出队后整体前移的顺序队列 | 不扩容时 O(1) | O(n) | 搬移元素开销大 |

## 十、讲义代码校正与易错点

> [!warning] 讲义代码用于理解思路，不宜逐字照抄
> - p.14 的 `#define STACK_INIT_SIZE 100;` 等宏定义应去掉末尾分号。
> - p.23–24、57–58 的局部指针 `p` 需要声明；`QNode/Qnode`、`QElemType/QelemType` 等名称大小写需要统一。
> - p.58 的 `retrun` 应改为 `return`。
> - p.34 的括号处理应分开写：左括号直接入栈，右括号匹配；不能把左括号套入普通运算符的弹栈规则。
> - p.76–77 的下标更新建议明确写成 `rear=(rear+1)%queuesize`、`front=(front+1)%queuesize`，避免照抄 `rear=++rear%...` 等依赖求值规则、难读的写法。
> - p.78 的出队示意 `Queue[front-1]` 没有完整表达回绕处理，实际代码应先取 `Queue[front]`，再更新 front。
> - `Status`、`OK`、`ERROR`、`OVERFLOW` 等是教学约定，需要自行定义；不能把常量名混用。

复习时优先检查：

1. 顺序栈的 `top` 指向下一空位，实际栈顶是 `top-1`。
2. Pop / GetTop / DeQueue 之前必须判空。
3. 顺序栈扩容后，要根据新的 base 恢复 top。
4. 链栈从表头操作；链队列从队尾插入、队头删除。
5. 链队列删空后，必须令 `rear=front`。
6. 后缀求值先弹右操作数，再弹左操作数。
7. 括号数量相等不代表匹配顺序正确。
8. 循环队列有 M 个单元，不一定能放 M 个元素。
9. 长度计算用 `(rear-front+M)%M`，不能直接用 `rear-front`。
10. 动态循环队列扩容要保持逻辑顺序，不能只改变容量。
11. 递归必须有终止条件，并持续缩小问题。
12. 递归调用次数、运行时间、调用栈深度需要分别分析。

## 十一、自测题（附答案）

### 题目

1. A、B、C 依次入栈，CAB 能否成为出栈序列？为什么？
2. 顺序栈 `top-base=4`，执行一次 Pop 后长度是多少？执行前栈顶在哪？
3. 为什么单链表实现栈时通常以表头为栈顶？
4. `[(])` 是否匹配？在哪一步失败？
5. 后缀表达式 `8 2 3 * -` 的结果是多少？
6. 把 `(A+B)*C-D/E` 转为后缀表达式。
7. 链队列只有一个数据结点时出队，需要额外更新哪个指针？
8. 循环队列 M=8，front=6，rear=2，当前长度是多少？
9. 保留一个空位时，M=8、front=6，队满时 rear 是多少？
10. 递归阶乘与汉诺塔的时间、辅助空间分别是什么量级？

### 答案

1. 不能。C 出栈后，B 压在 A 上方，只能先弹 B。
2. 长度 3；执行前栈顶为 `*(top-1)`。
3. 头插、头删都为 O(1)，不必遍历查找尾结点的前驱。
4. 不匹配。读到 `]` 时弹出 `(`，类型不匹配。
5. `8-(2*3)=2`。
6. `A B + C * D E / -`。
7. `rear`，令 `rear=front`，恢复只有头结点的状态。
8. `(2-6+8)%8=4`。
9. rear=5，因为 `(5+1)%8=6`。
10. 阶乘：时间 O(n)、调用栈空间 O(n)；汉诺塔：时间 O(2^n)、调用栈空间 O(n)。

## 十二、考前速记

```text
栈：后进先出，同一端入、同一端出。
顺序栈：top 指向下一空位；入栈先写后加，出栈先减后读。
链栈：表头即栈顶；头插头删。

队列：先进先出；队尾入、队头出。
链队列：front 指头结点；删空后 rear = front。
循环队列（留一个空位）：
  空：front == rear
  满：(rear + 1) % M == front
  长：(rear - front + M) % M
  容量：最多 M - 1 个元素

后缀求值：先弹右，再弹左。
中缀转后缀：数直接输出，运算符看优先级，括号单独处理。
递归：终止条件 + 更小的同类问题。
```
