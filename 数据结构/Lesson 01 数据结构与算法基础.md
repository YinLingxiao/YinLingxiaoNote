数据结构解决“**如何组织数据**”的问题

$$
\boxed{\text{Program} = \text{Data Structures} + \text{Algorithms}}

# 一、数据结构概述

计算机解决实际问题通常需要经历：

```TEXT
现实问题
↓
数学模型 / 数据模型
↓
算法
↓
程序
↓
结果
```

在实际问题中，并不是所有问题都能简单地用数学方程描述。

例如：

- 科学计算：根据三角形三边计算面积；
- 非数值计算：
    - 书目检索系统；
    - 学校组织管理系统。
    
对于后一类问题，不仅需要考虑“有哪些数据”，还必须描述**数据之间存在什么关系**。

因此，数据结构研究的核心为：

> **如何组织数据元素，以及如何表示数据元素之间的关系**

***
# 二、数据基本术语

## 1. 数据 Data

**数据**（Data）：能够被计算机处理或存储的各种符号的集合。

数据可以是：

- 文本
- 图像
- 音频
- 程序
- 其他形式的信息

## 2. 数据元素 Data Element

**数据元素**（Data Element）：数据的基本单位。一个数据元素通常可以由若干个数据项组成。

例如一个学生：

```TEXT
Student
├── StudentID
├── First Name
├── Last Name
└── Age
```

这里“一名学生”可以看作一个数据元素。

## 3. 数据项 Data Item

**数据项**（Data Item）：不可再分割的最小数据单位

例如学生数据中的：

- StudentID
- First Name
- Last Name
- Age

都是数据项。
因此：
```TEXT
数据元素
    ↓
由一个或多个数据项组成
```

## 4. 数据对象 Data Object

**数据对象**（Data Object）：具有相同性质的数据元素的集合

例如：
```TEXT
Desk = {desk1, desk2, ...}
Chair = {chair1, chair2, ...}
Student = {student1, student2, ...}
```

## 5. 基本关系

```TEXT
Data
│
├── Data Object
│      └── Data Element
│             └── Data Item
│
└── 数据可以包含多个不同的数据对象
```

# 三、数据结构的定义

## 1.定义

**数据结构**（Data Structure）：相互之间存在一种或多种特定关系的数据元素的集合
$$
$$
$$
\boxed{\textbf{Data Structure} = \textbf{Data Elements} + \textbf{Relationships}}
$$

## 2. 数学表示

数据结构可以表示为：
$$
\boxed{DS = (D, R)}
$$
其中：

- \(D\)：Data Elements 的集合；
- \(R\)：Data Elements 之间关系的集合。

所以一个数据结构包含两个核心部分：

```TEXT
数据元素集合 D
+
数据元素之间的关系 R
```

# 四、 逻辑结构与存储结构

数据结构可以从两个不同角度研究：

```TEXT
Data Structure
├── Logical Structure  逻辑结构
└── Physical Structure 存储结构
```

## 1.逻辑结构 Logical Structure

**逻辑结构**描述： 数据元素之间的逻辑关系

四类逻辑结构：

### （1）集合结构 Set

数据元素属于同一集合

### （2）线性结构 Linear Structure

数据元素之间形成线性关系。

典型特点：

```TEXT
A → B → C → D
```

### （3）树形结构 Tree Structure

呈现层次结构。

例如：

```TEXT
University
├── School 1
│   ├── Grade 1
│   └── Grade 2
└── School 2
```

主要表现为**一对多关系**。

### (4) 图结构 Graph Structure

数据元素之间形成更加复杂的网络关系。

主要表现为**多对多关系**。

## 2. 存储结构 Physical Structure

**存储结构**：数据结构在计算机内存中的实际存储方式。

不仅要存储：

- 数据元素本身；

还需要存储：

- 数据元素之间的关系。

课件列出的存储方式包括：

1. 顺序存储；
2. 链式存储；
3. 索引存储；
4. 哈希存储。

## 3. 顺序存储 Sequence Structure

特点：
> **数据元素存放在连续的存储空间中。**

```TEXT
地址      数据
0300      3.0
0302      4.5
...       ...
0668      2.3
```

## 4. 链式存储 Link Storage Structure

特点：
> **数据元素不要求存储在连续位置，通过指针表示元素之间的关系。**

```TEXT
┌──────┬──────┐
│ Data │ Next │
└──────┴──────┘
          ↓
       下一个元素
```


## 5. 逻辑结构与存储结构的关系

> **Algorithm design** depends on logical structure.

算法设计主要依赖**逻辑结构**

> **Algorithm implementation** depends on physical structure.

算法的具体实现依赖**存储结构**

```TEXT
逻辑结构
↓
决定算法如何设计

存储结构
↓
影响算法如何实现
```

# 五、数据类型

## 1. 数据类型 Data Type

**数据类型**：一组对象以及作用在这些对象上的一组操作

$$
\boxed{\text{Data Type} = \text{Objects} + \text{Operations}}
$$
例如对于整数类型：
```TEXT
对象：
整数值

操作：
+  -  *  /
```

## 2. 基本数据类型

又称：**原子类型 Atomic Type**

特点：
> **不可进一步分解**

例如：

- 整型
- 实型
- 字符型

## 3. 结构类型

特点：
> **可以进一步分解**

例如：

- 数组
- 线性表
- 树

# 六、抽象数字类型 ADT

### 1. ADT 的概念

**Abstract Data Type，抽象数据类型**

ADT 强调：

> 对象以及作用在对象上的操作的定义，与这些对象的具体表示方式和操作的具体实现相分离。

即：

```TEXT
关注：
这个数据对象“是什么”
+
可以对它“做什么”

而不是首先关注：
它具体“怎么实现”
```

## 2. ADT 的数学定义

ADT 可表示为三元组：
$$
\boxed{ADT = (D, S, P)}
$$
其中：

- \(D\)：Data Object，数据对象；
- \(S\)：Structure，数据元素之间的关系；
- \(P\)：Operations，作用在数据对象上的操作。

## 3. ADT 的一般定义格式

```TEXT
ADT ADT名称 {

    Data object:
        <数据对象>

    Data relationships:
        <数据关系>

    Operations:
        <操作定义>

} ADT名称
```

## 4. 操作的描述

一个操作通常写成：
```TEXT
OperationName(parameter list)

Initial Condition:
    前置条件

Result:
    操作结果 / 后置条件
```

# 七、算法 Algorithm
## 1. 算法的定义

**算法**（Algorithm）：为解决一个问题而执行的、有限且明确的一系列指令。

## 2. 算法的五个特性
### （1）有穷性 Finiteness

算法必须：

> 在有限步骤或有限时间后终止。

不能无限执行。


### （2）确定性 Definiteness

算法中的每一步：

> 都应该具有明确含义，不存在二义性。


### （3）可行性 Effectiveness

算法中的每一步：

> 都必须能够由基本操作经过有限次执行实现。


### （4）输入 Input

算法：

> 可以具有 0 个或多个输入。

### （5）输出 Output

算法：

> 至少具有一个输出。

```TEXT
有穷
确定
可行
输入
输出
```

## 3. 算法设计要求

### （1）正确性 Correctness

对于合法输入：

> 算法最终应停止并得到正确结果。

课件将正确性进一步描述为：

- 无语法错误；
- 对若干组输入得到正确结果；
- 对特殊输入得到正确结果；
- 对一切合理输入得到正确结果。

### （2）可读性 Readability

算法应该便于：

- 阅读；
- 理解；
- 交流。

### （3）健壮性 Robustness

对于不合理输入：

> 程序应该能够作出相应处理。

### （4）高效率和低存储量

即：

> High efficiency & low memory capacity。

希望算法：

- 时间开销小；
- 空间开销小。

## 4. 算法描述

算法可以通过多种方式描述：

- 自然语言；
- 程序设计语言；
- 流程图；
- 伪代码；
- 类 C 语言。

例如求数组最大值：
```C
int a_maxint(int a[], int n)
{
    int j, maxai = a[0];

    for (j = 1; j <= n - 1; j++)
        if (a[j] > maxai)
            maxai = a[j];

    return maxai;
}
```

其核心思想：
```TEXT
假设第一个元素为最大值
↓
依次与后面的元素比较
↓
如果发现更大元素
↓
更新最大值
```

# 八、算法复杂度分析

算法运行过程中主要消耗两类计算机资源：
```TEXT
时间 Time
空间 Space
```

## 1. 时间复杂度

### （1）算法运行时间的两种分析方式

##### 事后统计 Empirical

先实现程序，再实际运行并统计时间。

缺点：

运行时间会受到很多因素影响：

- 编程语言；
- 编译器；
- 计算机硬件；
- 软件环境。

##### 事前分析 Theoretical

不实际运行程序，而是：

> 根据算法本身估计其运行时间随问题规模增长的变化趋势。

### （2）问题规模

通常使用：n

表示问题规模。

例如：

- 数组中有 \(n\) 个元素；
- 对 \(n\) 个数据进行排序。

### （3）时间复杂度的核心思想

精确测量程序运行多少秒意义不大。

更加关注：

> **当问题规模 \(n\) 增大时，算法运行时间增长的趋势。**

这就是：

> **Time Complexity，时间复杂度**

## 2. Big O

课件使用渐近记号描述算法复杂度，包括：
```TEXT
O
Ω
θ
o
```

### (1) 语句频度
设问题规模为 \(n\)。

算法中基本操作执行次数的总和称为：

> **Frequency Count，语句频度**

记作：
$$f(n)$$
### (2) 时间复杂度
$$
\boxed{T(n) = O(f(n))}
$$
用于描述随着 $n$ 增大，算法运行时间的增长趋势。

### (3) Big O 的简化规则

分析时间复杂度时：
#### 忽略常数系数
例如：
$$O(7n^2) = O(n^2)$$
#### 忽略低阶项
例如：
$$O(n^3+7n^2+3) = O(n^3)$$
因此只保留：

> **增长最快的最高阶项。**

## 3. 时间复杂度计算

### 例 1：常量阶

```C
scanf("%d", &s);
s++;
printf("%d", s);
```

执行次数：

$$ f(n)=3 $$

因此：

$$ T(n)=O(3)=O(1) $$

即：

> **常量阶**
### 例 2：单层循环

```C
for (i = 0; i < n; i++)
    s = s + a[i];
```

循环执行约 \(n\) 次。

因此：

$$ f(n)=2n+2 $$

于是：

$$ \boxed{T(n)=O(n)} $$

即：

> **线性阶**
### 例 3：双层循环

```C
for (i = 1; i <= n; i++)
    for (j = 1; j <= n; j++)
        s++;
```

核心操作执行：

$$  1+2+···+n  $$

因此：

$$  \boxed{T(n)=O(n^2)} $$

即：

> **平方阶**
### 例 4：内层循环次数随外层变化

```
for (i = 1; i <= n; i++)
    for (j = 1; j <= i; j++)
        s++;
```

内层执行次数为：

$$ 1+2+\cdots+n \ $$

即：

$$ \frac{n(n+1)}2 \ $$

所以：

$$ T(n)=O(n^2) $$
## 4. 最好/最坏情况

对于同一个算法，不同输入可能造成不同运行时间。

因此可以区分：

- 最好情况；
- 最坏情况。

## 5. 常见复杂度

课件给出的增长速度关系：
$$
\boxed{O(1) < O(\log_2 n) < O(n) < O(n \log_2 n) < O(n^2) < O(n^3) < O(2^n) < O(n!) < O(n^n)}
$$
大致可以分为：

| 复杂度           | 名称    |
| :------------ | :---- |
| $O(1)$        | 常量阶   |
| $O(\log n)$   | 对数阶   |
| $O(n)$        | 线性阶   |
| $O(n \log n)$ | 线性对数阶 |
| $O(n^2)$      | 平方阶   |
| $O(n^3)$      | 立方阶   |
| $O(2^n)$      | 指数阶   |
| $O(n!)$       | 阶乘阶   |
### 复杂度运算规则

若：

$$
\begin{aligned}
T_1(n) &= O(f(n)) \\
T_2(n) &= O(g(n))
\end{aligned}
$$

则顺序执行：

$$
T_1(n) + T_2(n) = \max(O(f(n)), O(g(n)))
$$

即：

> 保留复杂度更高的一项。

如果两个过程嵌套：

$$
T_1(n) \times T_2(n) = O(f(n) \times g(n))
$$
